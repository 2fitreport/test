# 메인 홈 시스템 가이드

> 이 문서는 메인 홈 페이지에서 **각 직급별로 무엇이 보이고, 어떻게 동작하는지**를 설명합니다.

---

## 1. 직급 구분

| 직급 | 레벨 | 설명 |
|------|------|------|
| 대표자 | 1 | 회사 전체를 총괄하는 최고 관리자 |
| 대표실무자 | 2 | 실무를 총괄하는 관리자 |
| 실무자 | 3 | 문서를 배정받아 처리하는 담당자 |
| 영업자 (일반) | 4 | 기업을 등록하고 상담하는 영업 담당자 |
| 영업자 (소속대표) | 4 | 소속 영업팀의 대표 (같은 소속 영업자들을 관리) |
| 검수자 | 6 | 문서를 검수하는 담당자 |

---

## 2. 페이지 구성

메인 홈 페이지는 크게 **5개 영역**으로 구성됩니다.

```
┌─────────────────────────────────────────────────┐
│  ① 상단 통계 카드 (최대 5개)                      │
│  ┌───────┬───────┬───────┬───────┬───────┐      │
│  │진행중 │이번달 │이번달 │이번달 │이번달 │      │
│  │케이스 │승인금액│ 매출  │ 신규  │승인건수│      │
│  └───────┴───────┴───────┴───────┴───────┘      │
├──────────────────────┬──────────────────────────┤
│  ② 보완요청 알림      │  ③ 알림사항              │
│  (보완/보류 로그)      │  (메모/상태변경/배정 로그) │
├──────────────────────┴──────────────────────────┤
│  ④ 영업자 현황 (테이블)  │  ⑤ 진행상황 (차트)      │
│  - 등록, 진행, 승인,    │  - 진행단계별 막대차트   │
│    보류, 승인금액, 전환율 │  - 상태별 막대차트      │
└──────────────────────┴──────────────────────────┘
```

## 3. 영역별 상세 설명

---

### 3-1. 상단 통계 카드 (①)

| 카드 | 계산 방법 | 표시 조건 |
|------|----------|----------|
| 진행중 케이스 | 오늘 업데이트된 '진행' 상태 문서 수 | 모든 직급 |
| 이번달 승인금액 | 이번달 승인된 문서의 승인금액(approval_amount) 합계 (억원) | 모든 직급 |
| 이번달 매출 | 이번달 승인된 문서의 실제매출(revenue_amount) 합계 (억원) | **검수자·실무자 제외** |
| 이번달 신규 | 이번달 생성된 문서 수 | 모든 직급 |
| 이번달 승인 건수 | 이번달 승인된 문서 수 | 모든 직급 |

#### 날짜 기준
- **이번달**: 서버 기준 현재 월의 1일 ~ 말일
- **승인 판정**: `progress_details = '승인'` AND `updated_at`이 이번달 범위 내
- **신규 판정**: `created_at`이 이번달 범위 내
- **진행중 판정**: `progress_details = '진행'` AND `updated_at`이 오늘 이후

#### 금액 표시 형식
- 1억 이상: `X억 Y천 만원`
- 1천만 이상: `X천 만원`
- 1백만 이상: `X백 만원`
- 0원: `0 원`

---

### 3-2. 보완요청 알림 (②)

**보완/보류 상태 변경 로그**를 표시합니다.

- **분류 기준**: `action_type = 'status_change'` AND `new_value`가 '보완' 또는 '보류'
- **최대 표시**: 50건
- **읽음 관리**: `staff_read` JSONB 필드로 사용자별 읽음 상태 추적
- **미읽음 배지**: 빨간 원형 배지로 미읽음 수 표시

#### 기능
| 기능 | 동작 |
|------|------|
| 로그 클릭 | 읽음 처리 + 해당 문서 상세 페이지로 이동 |
| 전체 읽음 | 미읽음 로그 전체를 읽음 처리 (API 성공 시에만 UI 반영) |
| 전체 삭제 | 표시된 로그 전체를 DB에서 삭제 (API 성공 시에만 UI 반영) |
| 개별 삭제 | X 버튼으로 개별 로그 삭제 후 목록 재조회 |

---

### 3-3. 알림사항 (③)

**메모, 상태변경, 배정 로그**를 표시합니다.

- **분류 기준**:
  - `action_type`이 `memo_add`, `memo_delete`, `progress_details_change`, `manager_assigned`, `salesperson_assigned`
  - 또는 `action_type = 'status_change'` AND `new_value`가 '정상' 또는 '검수'
- **최대 표시**: 50건
- **프론트엔드 필터링** (LogItemList):
  - `memo_delete` 로그는 항상 숨김
  - `manager_assigned`는 레벨 1, 2만 볼 수 있음
  - `salesperson_assigned`는 레벨 1, 2, 4, 6만 볼 수 있음

#### 로그 표시 형식

| action_type | 표시 내용 |
|-------------|----------|
| status_change (정상) | `[정상] 상태로 변경되었습니다.` |
| status_change (검수) | `[검수] 상태로 변경되었습니다.` |
| memo_add | `[메모] 가 추가되었습니다.` |
| progress_details_change | `[진행단계명] 상태로 변경되었습니다.` |
| manager_assigned | `[실무자] 가 배정되었습니다. (담당자명)` |
| salesperson_assigned | `[영업자] 가 배정되었습니다. (영업자명)` |

---

### 3-4. 영업자 현황 (④)

**레벨 1(대표자), 2(대표실무자)만** 볼 수 있습니다. 다른 직급에서는 표시되지 않습니다.

#### 테이블 컬럼

| 컬럼 | 의미 | 계산 기준 |
|------|------|----------|
| 영업자 | 영업자 이름 | position_id = 4인 모든 사용자 |
| 등록 | 이번달 등록 문서 수 | created_at이 이번달인 문서 |
| 진행 | 현재 '진행' 상태 문서 수 | progress_details = '진행' (전체 기간) |
| 승인 | 이번달 승인 문서 수 | progress_details = '승인' AND updated_at이 이번달 |
| 보류 | 현재 '보류' 상태 문서 수 | status = '보류' (전체 기간) |
| 승인금액 | 이번달 승인금액 합계 | 이번달 승인 문서의 approval_amount 합계 |
| 전환율 | 등록 대비 승인 비율 | 승인 ÷ 등록 × 100 |

#### 기능
- **정렬**: 모든 컬럼 클릭 시 오름차순/내림차순 정렬
- **승인금액 정렬**: `approvalAmountRaw` (숫자 원본) 기준으로 정렬 (한글 형식이 아닌 실제 숫자)
- **페이지네이션**: 5건씩 표시
- **전환율 스타일**: 75% 이상 초록, 미만 주황

---

### 3-5. 진행상황 차트 (⑤)

**레벨 1(대표자), 2(대표실무자)만** 볼 수 있습니다.

#### 차트 구성
- **진행단계별 막대차트**: 상담신청, 서류요청, 분석, 심사, 진행, 승인요청, 승인
- **상태별 막대차트**: 정상, 보완, 보류, 검수

#### 월 선택
- 기본: 현재 월 (초기 데이터는 `/api/home` 응답에 포함)
- 월 변경 시: `/api/home?month=YYYY-MM&chart_only=true` 호출
- `chart_only=true` 모드에서는 로그, 통계, 영업자 데이터 조회를 **스킵**하여 성능 최적화

#### 문서 필터링
- 선택된 월에 **생성된 문서** (`created_at` 기준)만 차트에 반영

## 4. 직급별 데이터 범위

### 문서 조회 권한

| 직급 | 조회 범위 | 필터 조건 |
|------|----------|----------|
| 대표자 (1) | 모든 문서 | 필터 없음 |
| 대표실무자 (2) | admin 배정 제외 | `manager_id != 'admin'` |
| 실무자 (3) | 본인 담당 문서 | `manager_id = 본인 user_id` |
| 영업자 일반 (4) | 본인 문서 + 상담신청 문서 | `user_id = 본인` OR `submitter_id = 본인` |
| 소속대표 (4) | 소속 전체 영업자 문서 | 소속 → 영업자 → 문서 체인 조회 |
| 검수자 (6) | 담당 소속 문서 + 배정 문서 | 소속 기반 + `inspector_id = 본인` |

### 로그 조회 권한
- 모든 로그는 먼저 전체 200건을 조회한 후, **문서 권한에 따라 필터링**
- 본인이 볼 수 있는 문서의 로그만 표시됨

## 5. API 구조

### `/api/home` (GET)

메인 홈 데이터를 한 번에 조회하는 통합 API입니다.

#### 요청 파라미터
| 파라미터 | 타입 | 설명 |
|---------|------|------|
| month | string (YYYY-MM) | 차트에 표시할 월 (기본: 현재 월) |
| chart_only | boolean | true 시 차트 데이터만 반환 |

#### 응답 구조 (일반 모드)
```json
{
  "stats": {
    "inProgressCount": 5,
    "approvalAmount": 2.3,
    "monthlyRevenue": 1.5,
    "newRegistrations": 12,
    "approvedCount": 8
  },
  "revisionLogs": [...],
  "memoLogs": [...],
  "salesData": [...],
  "progressData": {
    "stage": { "labels": [...], "datasets": [...] },
    "status": { "labels": [...], "datasets": [...] }
  },
  "currentUserId": "user123",
  "userLevel": 1,
  "isRepresentative": false,
  "companyName": "회사명"
}
```

#### 응답 구조 (chart_only 모드)
```json
{
  "progressData": {
    "stage": { ... },
    "status": { ... }
  }
}
```

### `/api/documents/logs` (GET)

로그 조회 API. 개별 삭제 후 재조회 시 사용됩니다.

| 파라미터 | 용도 |
|---------|------|
| status_change_only=true | 보완요청 알림용 (보완/보류 로그) |
| memo_only=true | 알림사항용 (메모/상태/배정 로그) |
| include_read=true | 읽음 로그도 포함 |
| home_all=true | 보완요청 + 알림사항 한번에 조회 |

### `/api/documents/logs/[id]` (PATCH/DELETE)

| 메서드 | 동작 |
|--------|------|
| PATCH | 로그 읽음 처리 (staff_read 업데이트) |
| DELETE | 로그 삭제 (인증 + 역할 검증 필수) |

### `/api/documents/logs/[id]/read` (PATCH)

개별 로그 읽음 처리 (staff_read JSONB에 사용자별 true 설정).

### `/api/documents/logs/read-all` (POST)

복수 로그 일괄 읽음 처리. `bulk_mark_logs_read` RPC 호출.

### `/api/documents/logs/delete-all` (POST)

복수 로그 일괄 삭제. 요청 body의 `logIds` 배열에 해당하는 로그만 삭제.

## 6. 데이터 흐름

### 초기 로딩

```
페이지 진입 (page.tsx)
  ↓
fetch('/api/home') 호출
  ↓
API에서 유저 정보 + 로그 병렬 조회
  ↓
역할별 문서 필터링 쿼리 실행
  ↓
로그를 문서 권한으로 필터링
  ↓
통계 계산, 로그 분류, 영업자 현황, 차트 데이터 생성
  ↓
프론트엔드에 전달 → 각 컴포넌트에 분배
```

### 탭 복귀 시
```
visibilitychange 이벤트 감지
  ↓
document.visibilityState === 'visible'
  ↓
fetchHomeData() 재호출 → 전체 데이터 새로고침
```

### 로그 개별 삭제 후
```
LogDeleteButton 클릭 → DELETE /api/documents/logs/[id]
  ↓
성공 시 onLogDeleted 콜백 호출
  ↓
해당 로그 유형에 맞는 API 재조회:
  - 보완요청: /api/documents/logs?status_change_only=true&include_read=true
  - 알림사항: /api/documents/logs?memo_only=true&include_read=true
  ↓
로그 목록 갱신
```

### 월 변경 (차트)
```
월 선택 변경
  ↓
isCustomMonth = true
  ↓
fetch('/api/home?month=YYYY-MM&chart_only=true')
  ↓
차트 데이터만 갱신 (로그/통계/영업자 재조회 안 함)
```

## 7. 보안 규칙

- **로그인하지 않은 사용자**: 모든 API 접근 차단 (401 오류)
- **유효하지 않은 직급 (레벨 0 등)**: 모든 API 접근 차단 (403 오류)
- **직급별 데이터 격리**: 각 직급은 자신의 권한 범위를 넘는 문서/로그에 접근할 수 없음
- **로그 삭제/읽음**: 인증 + 역할 검증 필수 (미인증 요청 차단)
- **delete-all**: 요청한 logIds만 삭제 (전체 삭제 방지)
- **금액 계산**: parseInt NaN 가드로 비정상 데이터에 의한 통계 오염 방지
